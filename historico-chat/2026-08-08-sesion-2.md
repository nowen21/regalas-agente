Devuelve con `yield`, no con `return`. Es un **generador**.

En [comun.py:83](../validadores/comun.py#L83):

```python
def lineas_utiles(texto):
    dentro = False
    for n, linea in enumerate(texto.splitlines(), start=1):
        if _CERCA.match(linea):
            dentro = not dentro
            continue
        if not dentro:
            yield n, linea          # ← acá entrega
```

**La diferencia entre los dos:**

| | Qué hace |
|---|---|
| `return` | Entrega un valor y **termina** la función. No se vuelve a entrar. |
| `yield` | Entrega un valor y **pausa** la función. La próxima vez sigue en la línea siguiente, con todas sus variables como estaban. |

**Qué pasa cuando alguien la llama:**

1. `lineas_utiles(texto)` **no ejecuta nada** todavía. Devuelve un objeto generador, que es una promesa de ir entregando valores.
2. Cuando un `for` le pide el primero, el cuerpo arranca y corre hasta el primer `yield`. Ahí entrega el par `(n, linea)` y se congela.
3. Cuando el `for` pide el siguiente, la función **descongela justo después del `yield`** y sigue el bucle hasta el próximo.
4. Cuando el bucle interno se acaba, la función termina. Python avisa que no hay más y el `for` de afuera se corta solo.

**Por qué acá conviene que sea generador:** la variable `dentro` —que recuerda si vamos por dentro de un bloque de código— sobrevive entre una entrega y la siguiente. Con `return` habría que juntar todo en una lista y devolverla de golpe.

Así se ve del lado del que la usa, en `encabezados`:

```python
for n, linea in lineas_utiles(texto):    # pide un par, procesa, pide el siguiente
    m = _ENCABEZADO.match(linea)
```

Detalle práctico: como los valores se entregan de a uno y no se guardan, el generador **se recorre una sola vez**. Si hiciera falta recorrerlo dos veces, habría que hacer `list(lineas_utiles(texto))`. En el paquete nadie lo necesita: todos lo consumen con un `for` y listo.

Lo que sale es esto:

```python
[(12, "Ver la regla", "../base/09-git.md"),
 (30, "Pendiente 01", "../pendientes/01-validadores.md")]
 └── tupla ─────────────────────────────────────────┘
└── lista ───────────────────────────────────────────────────────────────┘
```

**Cómo lo escribí en los documentos:**

| Palabra en el documento | Qué es en Python | Cómo se escribe |
|---|---|---|
| lista | `list` — lo más parecido a un array | `[ ... ]` |
| par | tupla de 2 | `(a, b)` |
| trío | tupla de 3 | `(a, b, c)` |
| diccionario | `dict` — pares nombre → valor | `{ "clave": valor }` |

**La diferencia entre lista y tupla:** la lista se puede modificar —agregar, quitar, cambiar—; la tupla no, queda fija como nació. Por eso cada resultado individual es una tupla y el conjunto es una lista: se van agregando resultados a la lista, pero cada resultado ya no cambia.

**Dónde sí hay diccionarios:** cuando el documento dice «un diccionario de X → Y». Por ejemplo `citas.indice()`, que retorna `{"G2": ("base/09-git.md", "g2--primera-linea")}`: ahí se busca por el código de la regla, no recorriendo la lista entera.
